# RHYTHM V1.7.0 — Smart Goals & Recommendations

## จุดที่เพิ่มในเวอร์ชันนี้

- **เป้าหมายอัจฉริยะ** เพิ่มเมนูสร้างเป้าหมายพร้อมคำแนะนำจากข้อมูลย้อนหลัง 14 วัน (การนอน, โปรตีน, บันทึกอาหาร, วันฝึก, วิ่ง, Recovery, ชั่งน้ำหนัก)
- ตั้งเป้าหมายเองและปรับตัวเลข/วันเริ่ม/วันประเมินได้ ดูความคืบหน้าแบบ 7 วันล่าสุด **เฉพาะวันที่มีบันทึกจริงและไม่ก่อนวันเริ่ม**; เมื่อข้อมูลยังไม่ถึงขั้นต่ำจะมีข้อความเตือน; ไม่ตัดสินว่าเป็นเหตุและผล
- พัก/จบ/ลบเป้าหมาย, เขียน Reflection และคะแนน 1–5 โดยไม่แก้บันทึกสุขภาพต้นฉบับ
- **Auto-fill Workout Set Rows**: เมื่อเปิดบันทึกการฝึกจริง จะมีแถวตามจำนวนเซตในแผนพร้อมตัวเลข *เป้าหมาย* เบื้องต้น; ผู้ใช้ต้องติ๊ก “ทำแล้ว” ก่อนบันทึกเซตจริง เพื่อป้องกัน KPI และ Personal Record นับเซตที่ยังไม่ได้ฝึก
- เมื่อแก้ไข Workout Session ที่บันทึกแล้ว แถวจริงเดิมจะมีเครื่องหมาย “ทำแล้ว” และแสดงแถวเทมเพลตเพิ่มเติมหากบันทึกน้อยกว่าแผน; เพิ่ม/ลบเซตเองต่อได้

## วิธีอัปเดตจาก V1.6.0

1. ตรวจสถานะ Cloud ไม่มี Pending/Conflict แล้วส่งออกไฟล์ JSON สำรองจากหน้าโปรไฟล์
2. แตก **Update Only** ลง Repository V1.6.0 โดยคง `js/supabase-config.js` เดิม
3. Push ไป GitHub → Vercel จะ Deploy ให้; แนะนำ Hard Refresh 1 ครั้ง
4. ตรวจ Cloud Sync ด้วย 2 บัญชี/2 อุปกรณ์ และตรวจว่าท่า 3/4 เซตมีแถวพร้อมแต่ไม่ถูกนับก่อนเลือกทำแล้ว
5. **ไม่ต้องรัน SQL เพิ่ม**: `goals` เป็นฟิลด์เสริมใน Cloud JSON เดิม การเปลี่ยนข้อมูลยังใช้ conflict/revision protection ของ V1.1.0

## หมายเหตุความปลอดภัยและความถูกต้อง

- Goal progress ใช้ข้อมูลจริงหลังวันเริ่มและ 7 วันย้อนหลังถึงวันที่กำหนด/วันนี้ นับเฉพาะวันที่มีข้อมูล (ไม่ได้บันทึก ≠ 0) และไม่รวมข้อมูลที่ยังไม่ได้ทำจริง
- **เป้าหมายไม่ใช่คำแนะนำทางการแพทย์**: เป้าหมายนอน 7 ชั่วโมงสำหรับผู้ใหญ่เป็นแนวทั่วไป ไม่ประเมินการวินิจฉัยจาก Deep/REM ของนาฬิกา และเป้าหมายอาหาร/การวิ่งผู้ใช้ต้องปรับตามความเหมาะสม
- ระบบจะไม่อัตโนมัติ “จบเป้าหมาย” หรือซิงค์ข้อมูลปลอม ผู้ใช้เป็นผู้ยืนยัน
- เวอร์ชันนี้ไม่ได้เพิ่มตาราง SQL, ไม่เก็บข้อมูลอื่นนอก JSON เดิม, ไม่แก้ค่า Supabase config ใน Update Only
- เพื่อความปลอดภัยก่อนใช้จริง ให้ทดลองข้อมูลจำลองและสำรอง JSON ทุกครั้งก่อนอัปเดตใหญ่

## โครงสร้าง

- `js/goals.js`: สูตร/ข้อเสนอ/ตรวจข้อมูลเป้าหมาย
- `js/core.js`: การตรวจข้อมูลซิงค์/Backup และสร้างแถวเซตจากเทมเพลต
- `js/app.js`: ฟอร์ม หน้า Goals และ Workout Log
- `css/styles.css`: รูปแบบหน้า Goals และช่องบันทึกเซต
- `tests/test-v170.cjs`: การทดสอบ regression สำหรับฟีเจอร์ใหม่

# RHYTHM V1.6.0 — Deep Analytics & Personal Insights

> เริ่มจาก **V1.5.0**; เวอร์ชันนี้เพิ่มหน้าวิเคราะห์ข้อมูลอย่างละเอียดโดยไม่เปลี่ยนโครงสร้างการเก็บข้อมูลและไม่แก้ค่า Supabase Config

## มีอะไรใหม่

- หน้า **วิเคราะห์เชิงลึก** ใน Sidebar และ URL `#insights`
- เลือกช่วง 7 / 14 / 30 วัน และกรองรายหมวด **การนอน / โภชนาการ / น้ำหนัก / การฝึก / การวิ่ง / Recovery / ความสัมพันธ์ข้ามข้อมูล**
- คำอธิบาย 3 ส่วนสำหรับแต่ละข้อ: **สิ่งที่ข้อมูลบอก → แนวทางถัดไป → ความเชื่อมั่น**
- กราฟย้อนหลังกว่า 6 ด้าน พร้อมความครบถ้วนของข้อมูล (Coverage)
- **Sleep Deep Dive** แสดงชั่วโมงการนอนเมื่อเทียบคำแนะนำตามช่วงอายุและเป้าหมายส่วนตัว, Deep/Light/REM แบบเปอร์เซ็นต์และนาที, คืนที่นอนสั้น และความสม่ำเสมอของเวลาเข้านอน
- **Nutrition & Weight** แคลอรี่/โปรตีนเฉพาะวันที่บันทึก, น้ำหนักเฉลี่ย เทียบช่วงก่อน, และน้ำหนักเป้าหมาย โดยไม่ถือว่าวันไม่มีบันทึกคือวันที่กิน 0 kcal
- **Workout & Running** เปรียบเทียบ Session/RPE/Volume จริง, ระยะทางและ Pace แบบระบุแหล่งข้อมูลและข้อจำกัด
- **Recovery & Cross-Insights** ข้อมูลความเหนื่อยล้าและคู่วันที่มีทั้ง Sleep + Check-in (ต้องมีอย่างน้อยกลุ่มละ 3 วันจึงเริ่มเปรียบเทียบ)
- คำนวณผลใหม่เมื่อเปิดหน้าหรือสลับช่วงเวลา โดยไม่บันทึกผลวิเคราะห์ลง Cloud เป็นข้อมูลซ้ำ

## ความน่าเชื่อถือของข้อสรุป

- ตัวเลข **นาที/ชั่วโมง/กรัม/กิโลกรัม/เซต/ระยะทาง** มาจากบันทึกของผู้ใช้ ไม่ใช่การตรวจวัดของเว็บ
- ผู้ใหญ่อายุ 18–60 ปี CDC แนะนำให้พักผ่อนอย่างน้อย 7 ชม. ต่อคืน; อายุ 61–64 ปีประมาณ 7–9 ชม. และอายุ 65+ ประมาณ 7–8 ชม.
- ระยะ Deep/Light/REM ของนาฬิกาเป็นค่าประมาณ: ห้ามสรุปว่าร่างกายซ่อมแซมไม่พอ สุขภาพแย่ หรือมีปัญหาการนอนจากเปอร์เซ็นต์คืนเดียว
- **คำแนะนำเป็นแนวทางทดลองปรับพฤติกรรม ไม่ใช่คำสั่งรักษาหรือคำวินิจฉัย** ความสัมพันธ์ในกราฟไม่ใช่หลักฐานสาเหตุ
- รายงานแสดงช่วงเวลาที่ใช้และจำนวนวันที่มีข้อมูลเสมอ; อาหาร/น้ำหนัก/Check-in ที่ไม่มีการบันทึก **ไม่ถูกตีความเป็น 0**

อ้างอิง: [CDC Sleep](https://www.cdc.gov/sleep/about/) · [AASM adult sleep consensus](https://www.aasm.org/resources/pdf/adultsleepdurationconsensus.pdf) · [Wearable sleep-stage accuracy study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11511193/)

# RHYTHM V1.5.0 — Smart Workout Timer & Running Tracker

> อัปเกรดต่อจาก **V1.4.2** โดยไม่ลบแผน/ประวัติ/บัญชี Cloud เดิมและไม่เปลี่ยนตาราง Supabase

## สิ่งใหม่ใน V1.5.0

### Smart Workout Timer
- ใช้บนหน้า **แผนออกกำลังกาย** และ **บันทึกการวิ่ง** ได้
- **Countdown:** เลือกพัก 60/90 วินาที, เวลาพักจากแผน, เวลาเป้าหมายของท่าจับเวลา หรือระบุนาที+วินาทีเอง (สูงสุด 600 นาที)
- **Stopwatch:** นับเวลาเดินหน้า เหมาะกับ Plank, วิ่ง, หรือเซสชันที่ต้องการจับเวลาเอง
- หยุดชั่วคราว / ดำเนินต่อ / รีเซ็ตได้
- อิง `Date.now()` แทนนับจำนวน tick จึงแก้ความคลาดเคลื่อนจากการสลับแท็บหรือแท็บเบื้องหลังเมื่อกลับมาใช้งาน; sessionStorage ภายในแท็บช่วยกู้สถานะเมื่อ refresh
- เมื่อ Countdown ครบเวลา แจ้งด้วย Toast และพยายามส่งเสียงสั้น ๆ (เบราว์เซอร์อาจปิดกั้นเสียง); การแจ้งเตือน Desktop เป็นทางเลือก ต้องกดขออนุญาตและเปิดผ่าน HTTPS
- **ตัวจับเวลาไม่ได้บันทึกไป Cloud และไม่ได้บันทึกเป็น Workout Session/Run อัตโนมัติ** ผู้ใช้ต้องกดบันทึกกิจกรรมด้วยตนเอง

### Running Tracker
- แยกเป็นหน้าใน Sidebar ชื่อ **บันทึกการวิ่ง**; กรอกวันที่ ระยะทาง km ระยะเวลา นาที/วินาที ประเภท (Easy, Tempo, Intervals, Long Run, Race, Other), RPE, และหมายเหตุ
- สามารถเพิ่มหลายรายการต่อวันได้ รวมทั้งแก้ไข/ลบประวัติทีละรายการ
- Pace เฉลี่ยในรูป `นาที:วินาที ต่อกิโลเมตร` = **ระยะเวลาเป็นวินาที ÷ ระยะทาง km** แสดงรวม 7 วันแบบถ่วงตามระยะทางจริง
- แสดงระยะรวม 7 วัน / ระยะรวมสัปดาห์ปัจจุบัน (จันทร์–อาทิตย์) / Pace ที่เร็วที่สุดจากบันทึก / กราฟ 8 สัปดาห์
- ตั้งเป้าหมาย km ต่อสัปดาห์เองได้ และแสดงความก้าวหน้าโดย **ไม่กำหนดระดับการฝึกให้โดยอัตโนมัติ**
- ถ้าเปิด Stopwatch อยู่ สามารถใช้เวลา ณ ตอนเปิดฟอร์มเป็นค่าตั้งต้นของการวิ่งใหม่และแก้ไขก่อนบันทึกได้
- **เป็นการบันทึกด้วยมือ:** ไม่มี GPS, Route Map, เชื่อมสมาร์ตวอทช์, หรือการวัดอัตราการเต้นหัวใจอัตโนมัติ

## เก็บข้อมูลและข้อจำกัด

- `runs` และ `settings.runWeeklyGoalKm` เป็น **ฟิลด์ทางเลือก** ของ JSON Schema เวอร์ชันเดิม (`version:1`) จึงนำเข้าไฟล์สำรอง V1.0–V1.4.2 ได้โดยไม่ต้อง Migration

- Timer เป็นสถานะเฉพาะแท็บ (`sessionStorage`) ไม่ถูกแชร์ระหว่างเครื่อง และเบราว์เซอร์/อุปกรณ์อาจหยุดงานเมื่อปิดแท็บหรือปิดหน้าจอนาน ๆ ให้ตรวจเวลาที่แสดงเมื่อกลับมา ไม่ใช้แทนนาฬิกาที่ต้องแม่นยำต่อความปลอดภัย
- การบันทึก Pace จาก GPS/นาฬิกา ต้องกรอกระยะทางและเวลาจากแหล่งนั้นเอง ผลลัพธ์เป็นค่าประมาณจากข้อมูลที่กรอก

# RHYTHM V1.4.2 — Minute & Second Workout Timing

อัปเดตต่อจาก RHYTHM V1.4.1 โดยปรับฟอร์มท่าออกกำลังกายและฟอร์มบันทึกเซตจริงให้กรอก **นาที + วินาที** แทนการแปลงเองเป็นวินาทียาว ๆ ข้อมูลเก่า, คลังท่าส่วนตัว, ตัวคำนวณ Training Analytics และ Supabase Cloud Sync ยังใช้รูปแบบเดิม

## ฟีเจอร์ใหม่

- เมื่อเลือก **รูปแบบการทำ → จับเวลา** ช่อง **เวลาต่อเซต** แยกเป็น `นาที` (0–600) และ `วินาที` (0–59)
- ตัวอย่าง: Plank **1 นาที 30 วินาที** → นาที `1`, วินาที `30`; วิ่ง **30 นาที** → นาที `30`, วินาที `0`; Plank 45 วินาที → นาที `0`, วินาที `45`
- **บันทึกการฝึกจริง → เพิ่มเซตจริง** รองรับนาที + วินาทีแยกกันเช่นเดียวกัน และเปิดแก้ไขเซตเก่าได้
- ตารางฝึก, คลังท่าส่วนตัว และผล PR ที่เป็นเวลาจะแสดงผลอ่านง่าย (`30 นาที`, `1 นาที 30 วินาที`)
- ระบบเก็บค่า `targetSeconds`, `seconds` ภายในเป็น **จำนวนวินาทีเต็มเท่านั้น** (`30 นาที = 1800 วินาที`) เพื่อไม่เปลี่ยน JSON Schema และไม่กระทบสถิติที่มีอยู่
- ปฏิเสธเวลา 0, ค่าติดลบ, วินาที 60 ขึ้นไป และเวลารวมที่เกิน 10 ชั่วโมงต่อเซต โดยไม่เขียนทับข้อมูลก่อนหน้า

## วิธีอัปเดตเว็บที่ใช้ V1.4.1 อยู่แล้ว

1. เข้าเว็บ V1.4.1 ให้ Cloud Sync ไม่มี Pending/Conflict และดาวน์โหลด **Backup JSON** ก่อน
2. แตก `RHYTHM_v1.4.2_UPDATE_ONLY.zip` แล้วนำไฟล์ภายในไป **ทับตรง root** ของ GitHub Repository เดิม (ไม่ต้องเพิ่มโฟลเดอร์ครอบ)
3. ไฟล์ใน ZIP อัปเดต: `index.html`, `css/styles.css`, `js/app.js`, `js/core.js`, `tests/test-v142.cjs`, `README.md`, `CHANGELOG.md`
4. **ไม่มี** `js/supabase-config.js` ในไฟล์ Update Only; URL และ Publishable Key ที่คุณตั้งไว้ไม่ถูกทับ
5. Commit/Push ไป GitHub → รอ Vercel Deploy → Hard Refresh → ตรวจ footer ว่า **V1.4.2**
6. ลองสร้าง Plank 1 นาที 30 วินาที และวิ่ง 30 นาที; บันทึกเซตจริง; เปิดกลับมาแก้; ตรวจ Cloud Sync จากบัญชีจริงด้วยตนเอง

**ไม่ต้องรัน SQL ใหม่** ระบบยังใช้ JSON user document + RLS และ CAS sync ของ V1.1.0 ตามเดิม ส่วนการทดสอบกับ Supabase จริงยังไม่ได้ทำในสภาพแวดล้อมนี้

- เพิ่มตัวอย่าง Push-ups, Bench Dips, Bodyweight Squat และ Wall Sit; Plank/Pull-up/Run เดิมปรับเป็นประเภทที่เหมาะสมแล้ว

## คู่มือจาก V1.4.0 (ฟีเจอร์เดิมยังอยู่)


เว็บส่วนตัวสำหรับออกกำลังกายและวางแผนสุขภาพด้วย HTML/CSS/Vanilla JavaScript ต่อจาก RHYTHM V1.3.0 โดยยังรองรับบัญชี Supabase, Cloud Sync, Backup / Restore และตั้งค่าฟอนต์จาก Workday Journey เช่นเดิม

## ของใหม่ V1.4.0

- เพิ่มหน้า **Recovery & Lifestyle** ในเมนูด้านซ้าย เพื่อบันทึก **Recovery Check-in** รายวัน ย้อนหลังได้: ความสดชื่น/พลังงาน (1–5), ความเหนื่อยล้า (1–5), ความปวดเมื่อยกล้ามเนื้อ (1–5), ความเครียด (1–5), อารมณ์ (1–5), น้ำดื่มและก้าวเดิน (ไม่บังคับ), โน้ต รายการเก่ารองรับการแก้ไข/ลบ
- แสดง **ความรู้สึกเฉลี่ย** จากแบบประเมินตัวเอง (คะแนน 1–5; ไม่ใช่คะแนนตรวจสุขภาพ), กราฟแนวโน้ม 14 วัน, ปฏิทินย่อ 7 วัน, ชั่วโมงนอนเฉลี่ยจากบันทึกที่มีจริง, ความแปรปรวนของเวลาเข้านอนที่เคยบันทึกอย่างน้อย 3 คืน, RPE เฉลี่ยการฝึก 14 วัน
- สร้าง **ข้อสังเกตเชิงพฤติกรรม** เช่น มีข้อมูลว่าคืนล่าสุดนอนต่ำกว่าเป้าหมายเกิน 1 ชั่วโมง, เหนื่อย/ปวดกล้ามเนื้อสูง, ฝึกหนัก RPE ≥ 8 มากกว่า 1 ครั้งใน 3 วัน ทั้งหมดเป็นเงื่อนไขโปร่งใส แสดงเพื่อให้ผู้ใช้ตัดสินใจเอง **ไม่ปรับตารางฝึกหรือแคลอรี่ให้อัตโนมัติ**
- เพิ่มโลโก้ **ดัมเบลล์ + ปฏิทิน** ใน Sidebar, แถบหัวเว็บ, หน้า Loading และ Favicon บน Browser Tab พร้อม Apple Touch Icon

> **สำคัญ:** การประเมินความรู้สึก, ระยะการนอนจากนาฬิกา และข้อสังเกตเชิงการฝึกเป็นข้อมูลประกอบการวางแผน ไม่ใช่การประเมินโรคหรือบาดเจ็บ หากมีอาการเจ็บปวดผิดปกติหรือปัญหาสุขภาพ ให้ปรึกษาบุคลากรสุขภาพที่เหมาะสม

## ความปลอดภัย / ข้อมูลส่วนบุคคล

- `LocalStorage` **ไม่ถูกเข้ารหัส** เหมาะกับอุปกรณ์ส่วนตัว และไฟล์ JSON backup มีข้อมูลส่วนตัวจริง; อย่าแชร์โดยไม่ลบข้อมูลออกก่อน
- Cloud Sync ใช้ CAS revision เพื่อลดความเสี่ยงการเขียนทับจากสองเครื่อง, แต่กรณี Conflict ยังต้องเลือกว่าจะเก็บฝั่งใดทั้งชุด; สำรองทั้งคู่ก่อนทุกครั้ง
- ข้อมูล Check-in ที่บันทึกในอุปกรณ์จะรวมในไฟล์ JSON และถูกซิงค์ผ่านกลไกเดิมเมื่อเข้าสู่บัญชี Cloud
- Favicon เป็นไฟล์ Static ไม่มีข้อมูลผู้ใช้
- งานนี้ไม่เปลี่ยนรหัสผ่าน Supabase, RLS หรือตารางฐานข้อมูล
