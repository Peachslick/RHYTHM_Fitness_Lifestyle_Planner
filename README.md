# RHYTHM V1.9.3 — Everyday UX Upgrade

เวอร์ชันนี้ต่อยอด V1.9.2 โดยรักษา Account & Cloud Sync เดิม ไม่เพิ่ม SQL หรืออัปเดต RLS

## 1. Setup Wizard — 3 ขั้น

ไปที่ **โปรไฟล์และตั้งค่า → ตั้งค่าแบบทีละขั้น** หรือ **เริ่มต้นและคู่มือ** (ถ้ากด “เริ่มใช้ข้อมูลของฉัน” จากข้อมูลตัวอย่าง จะเปิด Wizard ให้อัตโนมัติ)

- **ขั้น 1:** ชื่อเล่น อายุ ส่วนสูง น้ำหนัก ค่าคงที่สูตร BMR
- **ขั้น 2:** ระดับกิจกรรม เป้าหมายหลัก น้ำหนักเป้าหมาย (ไม่บังคับ) และชั่วโมงนอนเป้าหมาย
- **ขั้น 3:** ค่าเพิ่ม/ลด kcal จาก TDEE, โปรตีนต่อกิโลกรัม และสัดส่วนพลังงานไขมัน
- กดถัดไป / ย้อนกลับได้โดยข้อมูลที่กรอกยังอยู่ และ **จะเขียนลงโปรไฟล์เพียงครั้งเดียวเมื่อกดบันทึกขั้นสุดท้าย**
- ผู้ใช้เดิมเลือกตั้งค่าแบบ Wizard ใหม่ได้โดยไม่ล้างประวัติ

## 2. Meal Templates — บันทึกทั้งมื้อในครั้งเดียว

1. ไปหน้า **โภชนาการ** เลือกวันที่และบันทึกอาหารในมื้อหนึ่ง เช่น ข้าว + ไข่ + นม อย่างน้อยครั้งแรก
2. กด **Meal Templates → สร้างเทมเพลตจากอาหารที่บันทึก** ตั้งชื่อและเลือกมื้อ
3. เมื่อวันอื่นกินมื้อคล้ายกัน เลือกวันที่ กด Meal Templates → **ใช้มื้อนี้** เพื่อเพิ่มอาหารทั้งหมดพร้อมจำนวนเสิร์ฟเดิมในครั้งเดียว
4. สามารถแก้แต่ละรายการหลังเพิ่ม หรือกลับไปลบเฉพาะเทมเพลตได้ โดยไม่กระทบอาหารที่เคยบันทึก
5. หากใช้เทมเพลตเดียวกันซ้ำในวันเดียว ระบบเตือนก่อนเพิ่มรายการซ้ำ

Meal Templates ถูกเก็บในข้อมูลบัญชี (`mealTemplates`) และอยู่ใน Export/Import JSON; ข้อมูลเก่าที่ไม่มีฟิลด์นี้ยังใช้งานได้

## 3. Live Workout Mode — ฝึกทีละเซตโดยไม่เปิด Modal

1. ไปหน้า **แผนออกกำลังกาย** เลือกวัน แล้วกด **เริ่มฝึกจากเทมเพลต**
2. เลือกท่า กรอกจำนวนครั้ง/น้ำหนัก หรือเวลา แล้วกด **จบเซตนี้ + เริ่มพัก**
3. ระบบนับเฉพาะเซตที่ยืนยันและเริ่ม Rest Timer ตามท่านั้น ใช้ปุ่มเลือกท่าหรือย้อนเซตล่าสุดได้
4. กรอกระยะเวลาฝึกและ RPE จากนั้นกด **จบและบันทึก Session** เพื่อเพิ่มประวัติจริง (หากมี Session เดิมในวันเดียวกันจะขออนุญาตแทนที่ก่อน)
5. สามารถปิดชั่วคราวและกลับมาฝึกต่อจาก Draft ได้ในแท็บเดิม โดยยังไม่ขึ้น Cloud จนกดยืนยันจบ

ข้อจำกัด: Draft ชั่วคราวเก็บใน sessionStorage ของแท็บและบัญชีปัจจุบัน ไม่ใช่ฐานข้อมูล Cloud และไม่ได้เข้ารหัสในเครื่อง อย่าพึ่งพาหากล้างข้อมูล/ปิดแท็บหรือใช้เครื่องสาธารณะ

## 4. Food Macro Estimates

- เพิ่มค่า Macro **แบบประมาณการ 183 รายการ** ที่เดิมทราบแค่ kcal (จาก HDmall) โดยไม่เปลี่ยน kcal เดิม
- แสดงป้าย “Macro ประมาณโดยระบบ” ในคลังอาหารและบันทึก
- ผู้ใช้แก้ค่าก่อนบันทึกได้; รายงานที่ต้องใช้ Macro ที่ตรวจสอบแล้วจะไม่ให้ข้อสรุปความเชื่อมั่นสูงจากค่าประมาณนี้
- อ่านคำอธิบายสูตรและข้อจำกัดใน `MACRO_ESTIMATION_TH.md` ซึ่งระบุแยกชัดว่า **HDmall ไม่ใช่ผู้ให้ตัวเลข Macro ประมาณเหล่านี้**

## การติดตั้งและข้อมูล

- ใช้ **Update Only** ทับ V1.9.2 โดยคงไฟล์ `js/supabase-config.js` เดิมไว้
- ไม่ต้องรัน SQL เพิ่ม; โครงสร้าง Cloud เป็น JSON เดิม และค่า Macro ใหม่จะปรากฏในคลังอาหารเมื่อเปิดเว็บหลัง Deploy
- ก่อน Deploy สำรอง JSON ตรวจ Pending/Conflict ของ Cloud และลองใช้งานบนบัญชีทดสอบก่อน
- การทดสอบ Chromium แบบโหลดซอร์สตรงผ่าน Desktop/Mobile แต่ **ยังไม่ได้ทดสอบ Supabase จริงและ Vercel ของผู้ใช้**

# RHYTHM V1.9.2 — UX Simplification & User Guide

**ต่อจาก V1.9.1 (337 อาหาร)** โดยคง Cloud Sync, เกณฑ์การวิเคราะห์ และข้อมูลสุขภาพเดิมทุกอย่าง ไม่มี SQL Migration

## มีอะไรใหม่

- **เมนู Sidebar จัดหมวด** บันทึกและวางแผน / วิเคราะห์และพัฒนา; ยุบ-กางได้และคงตำแหน่ง Scroll ขณะเปลี่ยนหน้า
- ปุ่ม **+ บันทึกด่วน** บนหัวเว็บ เปิดฟอร์มอาหาร การฝึก การนอน น้ำหนัก Recovery และการวิ่งได้โดยไม่ต้องเปิดหน้าใหม่ก่อน
- **หน้าเริ่มต้นและคู่มือ** (`#guide`): ตัวนับความพร้อมข้อมูล 14 วัน, สิ่งที่ต้องกรอก, ได้ผลวิเคราะห์อะไร และทางลัดไปหน้าใช้งาน
- **เมนูที่เคยกินอีกครั้ง**: ช่วยเพิ่มรายการอาหารย้อนหลัง (สูงสุด 6 เมนูที่ต่างกันใน 28 วันก่อนหน้า) ด้วยปริมาณเดิม ป้องกันคัดลอกซ้ำจากรายการต้นทางเดียวกัน
- คู่มือฉบับเต็ม: [USER_GUIDE_TH.md](USER_GUIDE_TH.md) (มีตารางข้อมูลที่จำเป็นของทุกระบบพร้อมข้อจำกัดการวิเคราะห์)

**วิธีอัปเดต:** Export JSON และตรวจ Sync ไม่มี Pending/Conflict → แตก Update Only ทับ Repository V1.9.1 เดิม → Push GitHub/Vercel → Hard Refresh → ทดลองจากเมนูเริ่มต้นและคู่มือ; ไม่ต้องรัน SQL ใหม่ และ Update Only ไม่รวม `js/supabase-config.js`

**ขอบเขต:** ยังไม่ได้ยุบลบหน้าวิเคราะห์เฉพาะด้าน, ไม่ได้สร้างสูตรสุขภาพใหม่, ไม่อ้างว่าใส่อาหารครบเพียงเพราะมีบันทึกบางมื้อ และไม่ได้ตรวจการซิงค์กับ Supabase Project จริงของคุณ

# RHYTHM V1.9.1 — Expanded Food Library (HDmall Reference)

> แพตช์ต่อจาก RHYTHM V1.9.0 เพิ่มเฉพาะคลังอาหารและการจัดการ Macro ที่ไม่มีข้อมูล **ไม่เปลี่ยน Supabase SQL, Auth, RLS หรือระบบ Cloud Sync**

## สิ่งที่เพิ่มและปรับ

- เพิ่ม **183 รายการ** จากตารางแคลอรี่อาหาร HDmall ที่เดิมไม่มีใน RHYTHM รวมเป็น **337 รายการ** (คลังเดิม 154 + ใหม่ 183) พร้อมแหล่งอ้างอิงแสดงในหน้าคลังและฟอร์ม เพิ่มชื่ออาหารจากหลายประเภท: ข้าวจานเดียว ก๋วยเตี๋ยว กับข้าว ต้ม/แกง ของว่าง ขนม ผลไม้ เครื่องดื่ม
- เลือกเฉพาะรายการอ้างอิงเป็น **ต่อจาน / ชาม / ถ้วย / ชิ้น / แก้ว ตามหน้า HDmall** โดยใช้พลังงานต่อหน่วยที่ระบุ ไม่สมมติน้ำหนักต่อ 100 กรัม ผู้ใช้แก้ตัวเลขตามเมนูจริงได้
- หน้า HDmall ให้ข้อมูลแคลอรี่ (kcal) ของเมนูต่อหน่วย แต่ไม่ได้ระบุ Macro ครบทุกเมนู เราจึงกำหนด `macroKnown:false` สำหรับอาหารใหม่ ไม่เดาโปรตีน คาร์บ และไขมัน ช่อง Macro ในฟอร์มเว้นว่าง และให้กรอกเองจากฉลาก/ข้อมูลที่ตรวจสอบได้หากต้องการ
- แคลอรี่จากรายการเหล่านี้ยังนำไปนับรวมตามจำนวนเสิร์ฟตามปกติ แต่ Dashboard/Nutrition จะแสดงคำเตือนเมื่อยอด Macro มีข้อมูลเพียงบางส่วน และรายงาน Metabolism / Insights / Goals จะ **ไม่นำวันที่ Macro ไม่ครบ** ไปสรุปว่าโปรตีนต่ำ
- ไม่ย้าย ไม่ลบ ไม่เปลี่ยนรายการเดิม เมนูส่วนตัว รายการโปรด ประวัติอาหาร หรือ Cloud Draft คลังอาหารเป็นข้อมูล Built-in ในโค้ด ส่วนบันทึกจริงยังอยู่ในข้อมูลบัญชีเดิม

**แหล่งอ้างอิงและตรวจสอบค่า:** https://hdmall.co.th/health-tools/food-calorie-table.html (เข้าถึง 21 ตุลาคม 2026)

**ขอบเขต:** อาหารหนึ่งจาน/ชามจากร้านต่างกันอาจมีน้ำหนักและส่วนผสมต่างกัน ค่าจึงเป็นเพียงประมาณการ; สรุป Macro ไม่ใช่ศูนย์ เพียงยังไม่มีข้อมูล และไม่สามารถแปลงเป็นกรัมโดยไม่มีข้อมูลน้ำหนักที่เชื่อถือได้

## วิธีอัปเดต V1.9.0 ที่ Deploy อยู่

1. เปิดเว็บเดิม ตรวจ Cloud Sync ว่าไม่มี Pending หรือ Conflict แล้วสำรองข้อมูล JSON
2. แตก `RHYTHM_v1.9.1_UPDATE_ONLY.zip` และคัดลอกไฟล์พร้อมโฟลเดอร์ย่อยไปทับ Repository เดิม
3. **ไม่ต้องแก้ `js/supabase-config.js` หรือรัน SQL ใหม่** (Update Only ไม่รวมไฟล์ Supabase Config)
4. Commit/Push GitHub ให้ Vercel Deploy; ถ้าคลังยังไม่เปลี่ยน ให้ Hard Refresh
5. เข้าโภชนาการ ตรวจคลังรวม 337 รายการ ค้นหา `ข้าวขาหมู` (690 kcal/จาน) หรือ `ผัดไทยกุ้งสดใส่ไข่` (545 kcal/จาน) เลือกบันทึกและตรวจว่าฟอร์มบอก “มีเฉพาะ kcal”
6. ตรวจซิงค์บัญชีจริงกับอีกอุปกรณ์ **หลัง Deploy** (ยังไม่ได้ทดสอบเชื่อม Supabase จริงในสภาพแวดล้อมพัฒนา)

## ไฟล์ใน Update Only

- `js/foods-hdmall.js` — คลังอาหารอ้างอิง 183 รายการใหม่ + ตัดชื่อซ้ำในขณะโหลด
- `js/app.js`, `index.html`, `css/styles.css` — ฟอร์ม/ค้นหา/ป้ายที่มา/คำเตือน/เวอร์ชัน Cache
- `js/core.js` — บันทึก/คำนวณแคลอรี่ได้แม้ Macro ยังไม่ทราบ พร้อมรองรับข้อมูลเก่า
- `js/metabolism.js`, `js/insights.js`, `js/goals.js` — วิเคราะห์ Macro เฉพาะวันที่มีข้อมูลครบ
- `tests/test-v191.cjs`, `README.md`, `CHANGELOG.md`

## QA

- ทดสอบชุดเดิม V1.0–V1.9.0 และชุดใหม่ `tests/test-v191.cjs` (47 assertions) ใน Node.js
- ทดสอบ Chromium/Playwright Desktop 1440×900 และ Mobile 390×844: โหลดหน้าโภชนาการ, ค้นหา, เปิดฟอร์ม HDmall, เพิ่ม 1.5 เสิร์ฟ, คิดพลังงานรวม, ตรวจคำเตือน Macro, ไม่เกิด JavaScript Error และไม่มี Horizontal Overflow
- Browser plugin ไม่พร้อมใช้ และ Chromium ของสภาพแวดล้อมบล็อก `localhost` / `file://` จึงใช้วิธีฉีด HTML/CSS/JS จากซอร์สเข้า Playwright เพื่อทดสอบหน้าที่มีปฏิสัมพันธ์; ไม่ใช่การทดสอบเซิร์ฟเวอร์ Vercel หรือ Supabase จริง

# RHYTHM V1.9.0 — Metabolism & Nutrition Insights + Sidebar Scroll Fix

> อัปเดตจาก **V1.8.0** โดยไม่เปลี่ยนฐานข้อมูล และไม่แตะ Supabase Config เดิมในชุด Update Only

## สิ่งที่ทำในเวอร์ชันนี้

1. เพิ่มเมนู **วิเคราะห์พลังงานและโภชนาการ** ใน Sidebar สำหรับดูผลย้อนหลัง 14 / 28 / 56 วัน
2. แสดง TDEE จากสูตรในโปรไฟล์, เป้าหมาย kcal, แคลอรี่และ Macro เฉลี่ยเฉพาะวันที่บันทึก, กราฟแคลอรี่และน้ำหนัก, สัดส่วนมื้ออาหาร และรายการอาหารบันทึกบ่อย
3. แสดงความครอบคลุมของการบันทึกอาหาร **โดยวันที่ไม่บันทึกเป็น Unknown ไม่ใช่ 0 kcal**
4. วิเคราะห์น้ำหนักด้วยค่าเฉลี่ยช่วงต้นและท้าย และเสนอแนวทางทบทวนพฤติกรรมแบบไม่ปรับเป้าหมายเอง
5. แบบจำลองพลังงานคงสภาพ (ตัวเลขหยาบจากการบันทึกอาหารและน้ำหนัก) แสดงเฉพาะเมื่อช่วงเวลาอย่างน้อย 28 วัน, อาหารมีบันทึก >=85% ของวัน และชั่งน้ำหนักสองวันขึ้นไปในสัปดาห์แรกและท้ายช่วง โดยใช้สมมติฐาน 7,700 kcal/kg ซึ่ง **ไม่เท่ากับการตรวจวัด TDEE** และอาจคลาดเคลื่อนมากเมื่อมีน้ำ/มวลกล้ามเนื้อเปลี่ยนหรือบันทึกมื้ออาหารไม่ครบ
6. แก้ Sidebar Scroll: เมื่อคลิกเปลี่ยนหน้า ระบบเก็บ `scrollTop` ของ Sidebar ก่อนสร้าง DOM ใหม่และคืนค่าให้หลัง Render ทั้งบน Desktop และ Mobile; การเปลี่ยนฟิลเตอร์ไม่ดึง Sidebar กลับไปด้านบน
7. ทุกการวิเคราะห์คำนวณจากข้อมูลเดิมในเครื่อง/Cloud โดยไม่เขียนผลวิเคราะห์ใหม่กลับลงฐานข้อมูล

## วิธีอัปเดตจาก V1.8.0

1. ตรวจการซิงค์ Cloud ว่าไม่มี **Pending/Conflict** และส่งออก JSON Backup สำรองก่อน
2. แตกไฟล์ `RHYTHM_v1.9.0_UPDATE_ONLY.zip` แล้วนำไฟล์ภายในไปทับ Repo เดิมโดย **รักษาโครงสร้างโฟลเดอร์**
3. ZIP Update Only **ไม่รวม `js/supabase-config.js`**; อย่าเอาค่าคีย์ลับหรือ service_role มาใส่ Frontend

- ใช้บนหน้า **แผนออกกำลังกาย** และ **บันทึกการวิ่ง** ได้
- **Countdown:** เลือกพัก 60/90 วินาที, เวลาพักจากแผน, เวลาเป้าหมายของท่าจับเวลา หรือระบุนาที+วินาทีเอง (สูงสุด 600 นาที)
- **Stopwatch:** นับเวลาเดินหน้า เหมาะกับ Plank, วิ่ง, หรือเซสชันที่ต้องการจับเวลาเอง
- หยุดชั่วคราว / ดำเนินต่อ / รีเซ็ตได้
- อิง `Date.now()` แทนนับจำนวน tick จึงแก้ความคลาดเคลื่อนจากการสลับแท็บหรือแท็บเบื้องหลังเมื่อกลับมาใช้งาน; sessionStorage ภายในแท็บช่วยกู้สถานะเมื่อ refresh
- เมื่อ Countdown ครบเวลา แจ้งด้วย Toast และพยายามส่งเสียงสั้น ๆ (เบราว์เซอร์อาจปิดกั้นเสียง); การแจ้งเตือน Desktop เป็นทางเลือก ต้องกดขออนุญาตและเปิดผ่าน HTTPS
- **ตัวจับเวลาไม่ได้บันทึกไป Cloud และไม่ได้บันทึกเป็น Workout Session/Run อัตโนมัติ** ผู้ใช้ต้องกดบันทึกกิจกรรมด้วยตนเอง

### Running Tracker
- แยกเป็นหน้าใน Sidebar ชื่อ **บันทึกการวิ่ง**; กรอกวันที่ ระยะทาง km ระยะเวลา นาที/วินาที ประเภท (Easy, Tempo, Intervals, Long Run, Race, Other), RPE, และหมายเหตุ
- สามารถเพิ่มหลายรายการต่อวันได้ รวมทั้งแก้ไข/ลบประวัติทีละรายการ
- Pace เฉลี่ยในรูป `นาที:วินาที ต่อกิโลเมตร` = **ระยะเวลาเป็นวินาที ÷ ระยะทาง km** แสดงรวม 7 วันแบบถ่วงตามระยะทางจริง
- แสดงระยะรวม 7 วัน / ระยะรวมสัปดาห์ปัจจุบัน (จันทร์–อาทิตย์) / Pace ที่เร็วที่สุดจากบันทึก / กราฟ 8 สัปดาห์
- ตั้งเป้าหมาย km ต่อสัปดาห์เองได้ และแสดงความก้าวหน้าโดย **ไม่กำหนดระดับการฝึกให้โดยอัตโนมัติ**
- ถ้าเปิด Stopwatch อยู่ สามารถใช้เวลา ณ ตอนเปิดฟอร์มเป็นค่าตั้งต้นของการวิ่งใหม่และแก้ไขก่อนบันทึกได้
- **เป็นการบันทึกด้วยมือ:** ไม่มี GPS, Route Map, เชื่อมสมาร์ตวอทช์, หรือการวัดอัตราการเต้นหัวใจอัตโนมัติ

## เก็บข้อมูลและข้อจำกัด

- `runs` และ `settings.runWeeklyGoalKm` เป็น **ฟิลด์ทางเลือก** ของ JSON Schema เวอร์ชันเดิม (`version:1`) จึงนำเข้าไฟล์สำรอง V1.0–V1.4.2 ได้โดยไม่ต้อง Migration
- บันทึกวิ่งจะใช้กลไกซิงค์ Snapshot ของ V1.1.0: เมื่อ Cloud มี Revision ใหม่กว่า จะให้ผู้ใช้แก้ไข Conflict แทนการเขียนทับโดยไม่บอก (ยัง **ไม่รวมรายการอัตโนมัติ**)
- ระบบไม่ล็อกการแก้ข้อมูล Running Tracker เพื่อแยกจาก Workout Session ซึ่งอาจเป็นการฝึกวันเดียวกันได้ — การบันทึกทั้งสองที่ควรนับเป็นคนละรายการต้องทำเอง
- Timer เป็นสถานะเฉพาะแท็บ (`sessionStorage`) ไม่ถูกแชร์ระหว่างเครื่อง และเบราว์เซอร์/อุปกรณ์อาจหยุดงานเมื่อปิดแท็บหรือปิดหน้าจอนาน ๆ ให้ตรวจเวลาที่แสดงเมื่อกลับมา ไม่ใช้แทนนาฬิกาที่ต้องแม่นยำต่อความปลอดภัย
- การบันทึก Pace จาก GPS/นาฬิกา ต้องกรอกระยะทางและเวลาจากแหล่งนั้นเอง ผลลัพธ์เป็นค่าประมาณจากข้อมูลที่กรอก

# RHYTHM V1.4.2 — Minute & Second Workout Timing

อัปเดตต่อจาก RHYTHM V1.4.1 โดยปรับฟอร์มท่าออกกำลังกายและฟอร์มบันทึกเซตจริงให้กรอก **นาที + วินาที** แทนการแปลงเองเป็นวินาทียาว ๆ ข้อมูลเก่า, คลังท่าส่วนตัว, ตัวคำนวณ Training Analytics และ Supabase Cloud Sync ยังใช้รูปแบบเดิม

## ฟีเจอร์ใหม่

- เมื่อเลือก **รูปแบบการทำ → จับเวลา** ช่อง **เวลาต่อเซต** แยกเป็น `นาที` (0–600) และ `วินาที` (0–59)
- ตัวอย่าง: Plank **1 นาที 30 วินาที** → นาที `1`, วินาที `30`; วิ่ง **30 นาที** → นาที `30`, วินาที `0`; Plank 45 วินาที → นาที `0`, วินาที `45`
- **บันทึกการฝึกจริง → เพิ่มเซตจริง** รองรับนาที + วินาทีแยกกันเช่นเดียวกัน และเปิดแก้ไขเซตเก่าได้
- ตารางฝึก, คลังท่าส่วนตัว และผล PR ที่เป็นเวลาจะแสดงผลอ่านง่าย (`30 นาที`, `1 นาที 30 วินาที`)
- ระบบเก็บค่า `targetSeconds`, `seconds` ภายในเป็น **จำนวนวินาทีเต็มเท่านั้น** (`30 นาที = 1800 วินาที`) เพื่อไม่เปลี่ยน JSON Schema และไม่กระทบสถิติที่มีอยู่
- ปฏิเสธเวลา 0, ค่าติดลบ, วินาที 60 ขึ้นไป และเวลารวมที่เกิน 10 ชั่วโมงต่อเซต โดยไม่เขียนทับข้อมูลก่อนหน้า

## วิธีอัปเดตเว็บที่ใช้ V1.4.1 อยู่แล้ว

1. เข้าเว็บ V1.4.1 ให้ Cloud Sync ไม่มี Pending/Conflict และดาวน์โหลด **Backup JSON** ก่อน
2. แตก `RHYTHM_v1.4.2_UPDATE_ONLY.zip` แล้วนำไฟล์ภายในไป **ทับตรง root** ของ GitHub Repository เดิม (ไม่ต้องเพิ่มโฟลเดอร์ครอบ)
3. ไฟล์ใน ZIP อัปเดต: `index.html`, `css/styles.css`, `js/app.js`, `js/core.js`, `tests/test-v142.cjs`, `README.md`, `CHANGELOG.md`
4. **ไม่มี** `js/supabase-config.js` ในไฟล์ Update Only; URL และ Publishable Key ที่คุณตั้งไว้ไม่ถูกทับ
5. Commit/Push ไป GitHub → รอ Vercel Deploy → Hard Refresh → ตรวจ footer ว่า **V1.4.2**
6. ลองสร้าง Plank 1 นาที 30 วินาที และวิ่ง 30 นาที; บันทึกเซตจริง; เปิดกลับมาแก้; ตรวจ Cloud Sync จากบัญชีจริงด้วยตนเอง

**ไม่ต้องรัน SQL ใหม่** ระบบยังใช้ JSON user document + RLS และ CAS sync ของ V1.1.0 ตามเดิม ส่วนการทดสอบกับ Supabase จริงยังไม่ได้ทำในสภาพแวดล้อมนี้

- เพิ่มตัวอย่าง Push-ups, Bench Dips, Bodyweight Squat และ Wall Sit; Plank/Pull-up/Run เดิมปรับเป็นประเภทที่เหมาะสมแล้ว

3. หากต้องการ Cloud ให้สร้าง Supabase project และใช้ `supabase/001_init.sql` **เพียงครั้งแรกของโปรเจกต์ใหม่เท่านั้น** แล้วตรวจ `supabase/VERIFY_SETUP.md`
4. กรอก URL และ **Publishable Key** ใน `js/supabase-config.js` (ห้ามใช้ `service_role`, secret key หรือใส่รหัสผ่านฐานข้อมูล)
5. กำหนด Authentication URL Configuration และ Redirect URLs ให้รองรับ URL Vercel ที่ใช้งาน แล้วทดสอบการยืนยันอีเมล/รีเซ็ตรหัสผ่าน

**หมายเหตุ:** ถ้าใช้ Full Source เพื่อทับโปรเจกต์เก่าที่ตั้งค่า Supabase แล้ว จะต้องเก็บ `js/supabase-config.js` เดิมไว้เอง มิฉะนั้น Cloud จะกลับเป็นโหมดไม่ได้ตั้งค่า และ **อย่ารัน `001_init.sql` ซ้ำในโปรเจกต์เดิมโดยไม่ตรวจสอบ**

## ความปลอดภัย / ข้อมูลส่วนบุคคล

- `LocalStorage` **ไม่ถูกเข้ารหัส** เหมาะกับอุปกรณ์ส่วนตัว และไฟล์ JSON backup มีข้อมูลส่วนตัวจริง; อย่าแชร์โดยไม่ลบข้อมูลออกก่อน
- Cloud Sync ใช้ CAS revision เพื่อลดความเสี่ยงการเขียนทับจากสองเครื่อง, แต่กรณี Conflict ยังต้องเลือกว่าจะเก็บฝั่งใดทั้งชุด; สำรองทั้งคู่ก่อนทุกครั้ง
- ข้อมูล Check-in ที่บันทึกในอุปกรณ์จะรวมในไฟล์ JSON และถูกซิงค์ผ่านกลไกเดิมเมื่อเข้าสู่บัญชี Cloud
- Favicon เป็นไฟล์ Static ไม่มีข้อมูลผู้ใช้
- งานนี้ไม่เปลี่ยนรหัสผ่าน Supabase, RLS หรือตารางฐานข้อมูล
